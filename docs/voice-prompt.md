STAGE B: BUILD (after my go; in waves, adapt to the picks)
WAVE 1: POLICY AND CONFIG (cheap, biggest naturalness gains)
B1. ONE MODE. Remove the separate modes and toggles (Stay Awake, wake-word-only, the Voice ID switch, the Microphone Mode menu, Start/Stop Listening as a mode). What remains, automatically:
  - AT THE MAC (unlocked, input in the last ~5 min, not on a call): she listens continuously and answers when I'm talking to her (no wake word needed).
  - AWAY / idle / locked / on a call or in a meeting: only "Hey ARES" wakes her ("ARES" alone only at a stricter threshold or inside an open conversation).
  - Always available: the corner orb's hold-to-talk, ⌥Space, "go quiet" / "stop listening" (until I'm back or say "I'm back"), one ◉ item "Mute Microphone" (a hard mute, shown in the bar).
  - Migrate settings silently; keep standby/ignition behaviour (ears after the wake). Mic Mode: observe it (preferredMicrophoneMode is read-only) and offer the system picker only if measurements show Voice Isolation helps.
B2. END OF TURN: the A5 pick (likely 0.2 s VAD stop → Smart Turn v3.2 + transcript cues + cap), adapting to my typical pauses over time. Fallback: the old timer.
B3. FOLLOW-UPS: replace the flat 20 s window with a decaying one: easy for the first ~6 s after her reply, then more evidence needed; longer when she asked me a question; a visible listening cue while it's open.
B4. BARGE-IN: duck her voice on speech onset, confirm (≥ ~0.5 s of real words, not "mm-hm"/a cough), then stop; resume after ~2 s if nothing followed. "Stop / wait / hold on" always stops at once. Tell Claude exactly what I heard before the cut (comms.js word timing).
B5. VOICE TRUST, FIRST PASS (no more "voice not recognised"): whole-utterance scoring, < 1 s = no evidence, score against all enrolment vectors, threshold set from live labelled scores (A3), not enrolment clips. Remove the retrain nags; keep "retrain my voice" on request.
B6. SPEED POLICIES: route quick turns to Haiku 5.5 at low effort (A7), keep the system prompt and tool list byte-stable across the session (any change invalidates the prompt cache), trim/defer rarely used MCP tools (tool search where available), have Claude say one short line before a tool call (a cached "One sec." only if nothing has been said by ~1.5 s), slow work as background jobs reported later. Preemptive generation: start the brain on a confident end of turn and cancel if I keep talking; never start ElevenLabs early (credits).
B7. INTERIM HEARING + TONE: the custom language model with the X-SAMPA "Ares" (if A4 shows a gain); voice.js: pass audio tags for v4 models too (not only eleven_v3) and fix the cue regex for combined tags ("[whispering, playful]") with a whitelist; a short hedged TONE NOTE for Claude built from the recogniser's voice analytics (rate, pauses, pitch, jitter/shimmer) against MY baseline, only when clearly different, only for speech addressed to her, never stored; prompt rule (Hume-style): adjust style, don't name the emotion, watch for word/tone mismatch, calm rather than mirror stress.

WAVE 2: NEW COMPONENTS
B8. "HEY ARES" CASCADE: (1) the A2 livekit-wakeword model on 80 ms frames, high recall, with Siri's near-miss window (a near miss lowers the threshold for a few seconds so a normal-volume repeat triggers); (2) sherpa-onnx KWS "HEY ARES" verifies the ~1.5 s candidate; (3) the trust check; (4) a cheap text check dropping non-vocative mentions ("I was reading about Ares…"). Self-trigger guard: raise stage 1's threshold while she speaks and drop detections that line up with her own scheduled "Ares" (comms.js timing). It must not need SFSpeech running; measure CPU. A quiet chime + the orb/reactor pulse confirm a wake.
B9. HEARING: SpeechTranscriber (macOS 26) for live partials/captions; Parakeet TDT via FluidAudio as the batch final pass for each finished command, with vocabulary aliases (Aries/Harris → ARES, contacts, apps, projects). Never drop the first word after the wake phrase.
B10. TTS: Katherine on eleven_v4_turbo over the Text to Dialogue WebSocket with streamed text deltas (if A7 passed), Flash v2.5 then Kokoro as fallbacks; keep the phrase cache; audio tags used sparingly (one per clause at most).
B11. TRUST SCORE: the A3 speaker model + AS-norm + calibration, fused with presence (input in the last minute, unlocked), near-field cues, the Mac's own playback (A6 reference), and a session window after a confident match. Policy by tier: questions/chat/my info/timers/opening things → "me at the Mac" is enough; tier 2 → good trust; tier 3 → my explicit yes on screen/phone, never voice alone. When unsure she stays quiet (a tiny "not sure" dot on the orb/reactor); borderline + near-field + present + low-risk → answer and learn under voiceid's rules.
B12. ADDRESSED CHECK: keep addressed.js's rules as triggers/vetoes; add a small calibrated classifier over owner-relative prosody, recogniser confidence, dialogue context, call/media state (and face presence if Vision is on); Apple's on-device Foundation Model only as a tie-breaker for unclear cases; run at high precision.
B13. INTENT: tiers sharing ONE action registry: (0) a fixed grammar for the hottest commands, (1) nearest-neighbour embedding routes with per-route thresholds, a margin over the runner-up and near-miss negatives, executing only reversible tier-1 actions, (2) optional prewarmed Apple Foundation Models @Generable intent/slot extraction with a "needs the brain" output, (3) Claude. A shared entity resolver (contacts, apps, files: phonetic + spelling + recency + learned aliases → a short candidate list), ARES-owned dialogue state (last actions, salient and on-screen entities as text; short follow-ups rewritten before routing), alternatives/low-confidence spans passed forward. Confirmation by risk: reversible → state the result; close entity match → one question; tier 3 → explicit read-back.
